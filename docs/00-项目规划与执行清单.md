## 一、项目目标

以"用户智能护肤 + 医护专业赋能 + 后台高效运维"为核心业务闭环，做一套轻量的肌肤养护系统。核心是三件事：用户说不清自己什么肤质、看到问题判断不准、平时没人给专业指导。

**落地形态**（与用户对齐后的既定决策）：

| 维度 | 决策 |
|------|------|
| 后端 | Node.js（Express）+ SQLite（零配置，可迁移 MySQL/云数据库） |
| 管理端 | Vue3 + Vite + Element Plus |
| 小程序端 | uni-app（Vue3 + Vite），可编译微信小程序与 H5 |
| AI 能力 | 可插拔 AI 层：DeepSeek（文本 `deepseek-chat` + 视觉 `deepseek-v4-flash-vision-exp`）+ 本地色彩学启发式引擎兜底（无 Key/离线时可用） |
| 认证鉴权 | JWT 无状态 + RBAC 角色权限 + 动态菜单 |
| 交付范围 | MVP 核心闭环（用户端 / 管理端 / 医生端） |

参考文章里提到的四个难点（小程序跨域、JWT 会话安全、AI 接口容错、RBAC 多角色隔离），这个项目都实际做了一遍。

## 三、技术架构

```
┌───────────────┐   ┌────────────────┐   ┌──────────────────┐
│  小程序端 uni-app │   │  管理端 Vue3      │   │  AI 分析层(可插拔)  │
│ (微信小程序/H5)  │   │ (Element Plus)   │   │ 本地引擎 ⇄ DeepSeek │
└───────┬───────┘   └───────┬────────┘   └────────┬─────────┘
        │  HTTPS/REST        │  HTTPS/REST           │
        └──────────┬─────────┴───────────┬──────────┘
                   ▼                      ▼
        ┌─────────────────────────────────────────┐
        │        Node.js (Express) 后端           │
        │  JWT 认证 · RBAC 授权 · 统一响应 · 日志   │
        │  文件上传 · AI 容错重试 · 跨域 CORS       │
        └──────────────────┬──────────────────────┘
                           ▼
                   ┌─────────────────┐
                   │   SQLite 数据库  │  (可迁移 MySQL/云数据库)
                   └─────────────────┘
```

**工程难点落地策略**：
1. **小程序跨域** → 后端统一 CORS + 白名单配置；H5 开发期代理，生产期 HTTPS 域名。
2. **JWT 会话** → 双鉴权体系：后台用户 `Authorization`、小程序用户 `Wx-Authorization`（借鉴 ruoyi-vue-wxmini 的隔离方案）。
3. **AI 容错** → AI 分析层二次封装：鉴权/超时重试/异常捕获/参数校验，图片过大或画质异常拦截提示。
4. **RBAC 动态菜单** → 后端返回权限树，前端递归渲染菜单 + 路由守卫 + 接口级鉴权。

## 六、里程碑与交付节奏

- S0–S2（规划期）：先出 3 份文档（本规划、PRD、架构设计），后面编码就照着它走。
- S3（实现期）：三端代码和数据库脚本一次做完，工程师再过一遍全局一致性。
- S4（验证期）：QA 写核心用例并跑起来，有问题就修，最多两轮回归。
- S5（交付期）：主理人整理文件清单、启动命令、测试通过率和已知问题。
